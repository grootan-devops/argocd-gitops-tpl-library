# Migration Guide

This document records required consumer actions when upgrading between releases.
Breaking changes must include an entry before release.

To upgrade, apply every section after your pinned version up to the target, oldest first.
Newer sections are split into **Required** (the upgrade breaks or misbehaves without it),
**Recommended** (aligns an existing environment with the current standards) and **Verify**.

## 1.7.0

### Required

Update both consumer library pins to `1.7.0` and rebuild dependencies. Before using
`plugin.skipCrds`, update the registered CMP script to consume
`ARGOCD_ENV_HELM_SKIP_CRDS` as shown in the plugin guide. The library configures the
Application environment; it does not install or update the CMP script.

### Verify

Omitted or `false` includes CRDs; `true` excludes them. Review rendered CRDs before
syncing, especially when another Application owns them. Native Helm sources remain unchanged.

## 1.6.0

### Required

No migration is required for existing Applications. Update the library pin in both
consumer `Chart.yaml` files to `1.6.0` and rebuild their dependencies.

## 1.5.0

### Required

No migration is required for existing native Helm Applications. Update the library
pin in both consumer `Chart.yaml` files to `1.5.0` and rebuild their dependencies.

## 1.4.0

### Required

No migration required. The templates, values and generated Application names are unchanged;
this release documents the `apps` registry, the environment starter files and the GitOps
README convention.

### Recommended

- Record the cluster label and the Argo CD cluster name in the GitOps repository's
  default-branch README, as the root Application guide shows.
- Keep only what differs per environment in each `values/` file, as listed under what a values
  file overrides; a setting every environment needs belongs in the service chart.

### Verify

- `helm template` on the root chart and on `extras/` renders the same Application names as
  before the upgrade.

## 1.3.0

No consumer migration required. Chart CI and verification container images upgraded to `grootantech/toolkit:1.1.0` and reusable workflow callers pinned to `github-ci-library` `@1.4.0`.

## 1.2.0

### Breaking Changes

- **Mandatory `cluster` configuration:** `values.cluster` is now strictly required. Helm template generation fails if `cluster` is omitted:

  ```yaml
  # values.yaml
  cluster: "midgard" # or your cluster identifier
  ```

- **Argo CD Application Naming Convention:** Application resource names generated by the chart now include the cluster segment (`<chart>-<cluster>-<segments>-<env>` instead of `<chart>-<app>-<env>`). Because `metadata.name` changes, existing Application resources will be replaced upon upgrading. Plan application recreation or state migration accordingly.
- **Rejection of `renderExtrasManifests`:** `renderExtrasManifests: true` is no longer supported and triggers a template failure. Raw manifests must be placed in named directories under `tests/extras/manifests/<app>/` and reconciled through generated Extras Applications.

## 1.1.0

No consumer migration required. GitHub Actions reusable workflow references pinned to `github-ci-library` 1.0.0.

## 1.0.0

No migration is required for the initial release.
