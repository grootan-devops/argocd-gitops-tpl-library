# Migration Guide

This document records required consumer actions when upgrading between releases.
Breaking changes must include an entry before release.

## 1.2.0

### Breaking Changes

- **Mandatory `cluster` configuration:** `values.cluster` is now strictly required. Helm template generation fails if `cluster` is omitted:

  ```yaml
  # values.yaml
  cluster: "midgard" # or your cluster identifier
  ```

- **Argo CD Application Naming Convention:** Application resource names generated by the chart now include the cluster segment (`<chart>-<cluster>-<segments>-<env>` instead of `<chart>-<app>-<env>`). Because `metadata.name` changes, existing Application resources will be replaced upon upgrading. Plan application recreation or state migration accordingly.
- **Rejection of `renderExtrasManifests`:** `renderExtrasManifests: true` is no longer supported and triggers a template failure. Raw manifests must be placed in named directories under `tests/extras/manifests/<app>/` and reconciled through generated Extras Applications.

## 1.1.0

No consumer migration required. GitHub Actions reusable workflow references pinned to `github-ci-library` 1.0.0.

## 1.0.0

No migration is required for the initial release.
